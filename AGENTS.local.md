# Working agreements

## Finish changes with a commit and push

For any task that changes repository files, automatically commit and push the finished changes before your final response once the requested work is complete and verified. This includes documentation and configuration edits. No additional confirmation is needed.

- Review the diff and run checks appropriate to the change. Fix task-related failures before committing; report any unresolved blockers honestly.
- Commit only changes belonging to your task. Preserve unrelated or concurrent work in the workspace.
- Write a concise commit message and push the current branch to its existing upstream. Use a normal push and preserve remote history.
- Create tags or releases only when the user requests them.
- Respect an explicit instruction to leave changes uncommitted, avoid pushing, or wait for review.
- In the final response, report the commit, destination branch, and relevant verification results. If committing or pushing fails, explain the failure and what remains.
